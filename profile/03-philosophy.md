# Engineering Philosophy

I believe software should solve real problems before showcasing technology.

Good engineering is not measured by the number of frameworks used, but by how
well a solution can be understood, maintained, and evolved.

When possible, I prefer modular systems, clear documentation, and practical
architectures over unnecessary complexity.

---

# AI Philosophy

Artificial Intelligence is a tool for extending human capability.

The value of AI lies in solving meaningful problems, automating repetitive
tasks, and helping people make better decisions.

I am more interested in building AI products than training isolated models.

---

# Product Philosophy

Every feature should exist for a reason.

Before implementing a feature, I prefer understanding:

- Who benefits?
- What problem does it solve?
- Can it scale?
- Can it be maintained?

Technology should support the product, not become the product.

---

# Learning Philosophy

My primary learning cycle is:

Research
→ Experiment
→ Build
→ Reflect
→ Improve

Real projects are my preferred learning environment.

---

# Decision Framework

When evaluating technologies, I generally prioritise:

1. Practicality
2. Scalability
3. Simplicity
4. Maintainability
5. Learning value
6. Cost efficiency

I avoid adopting technology only because it is popular.

---

# Working Principles

- Build first, optimise later.
- Documentation is part of development.
- Automation is better than repetitive manual work.
- Every project should improve the previous one.
- Curiosity should always be followed by experimentation.

---

# Continuous Improvement

Areas of ongoing growth include:

Learning never ends; each completed project becomes the foundation for the next.
